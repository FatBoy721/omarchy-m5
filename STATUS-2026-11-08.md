### Earlier GPU gate (before the stub refresh)
- Today: llvmpipe only. Our GPU candidate is compiled (offline) but **hard-disabled on J714s**.
- **Current-firmware gate (P):** the public G17S driver work, [aurora-silicon/linux #1173](https://github.com/aurora-silicon/linux/pull/1173) (open), targets **27.2/27.3** firmware. Its PR body lists 27.2 on hardware as not exercised yet. The only hardware result is **27.3b1 on J716s** (REPORTED). The firmware is pre-loaded by iBoot, so a 26.x stub can't run it, and **nothing public exists for 26.x on M5** *(P, as far as we've read)*.
- **J714s voltage blocker (P):** our J714s ADT GPU `perf-states` differ from #1173's J716S table in 13 of 14 states. The J716S table sits **5-15 mV below** this part's bins at several states, so we refuse to init with it.
  - The J714s `perf-states-sram` holds a constant **1385** at every state, a different encoding from J716S's max(775, core). Its meaning is **U**.
- **No promise:** GPU acceleration needs a correct J714s table and admitted G17S firmware (a stub recreate the owner hasn't approved). No public source shows 27.2 GPU working on any M5 Pro.

### Wi-Fi (N1)
- **First native activation (build 3408) FAILED.**
  - The machine reset about 17 s after the runtime power-up trigger, and the safety guards returned it to macOS cleanly.
  - The full journal of that boot has **no kernel line after the trigger** (lazy journald syncing, so the tail isn't proof either way). **The cause is unknown.**
- **Afterwards:** two real source defects were found in our *unpublished* sequence:
  - the PCIe host power domain made the adopt probe refuse;
  - pinctrl was enabled without `gpio-reserved-ranges`, and a pin-112 read is a documented SError on the public J716c DT.
  - Neither is proven to be the cause.
- **Build 3410:** fixes both and splits the trigger into stages, running only stage 1 (power domains already proven natively) and stage 2 (pinctrl with reserved ranges). PCIe link training stays held. **It is source- and packet-reviewed only; it has not been tested natively, and there is still no Wi-Fi.**
- Public base: [#937 adopt trained root ports](https://github.com/aurora-silicon/linux/pull/937), [#938 N1 Wi-Fi/BT on bare-metal T6050](https://github.com/aurora-silicon/linux/pull/938) (both open).
