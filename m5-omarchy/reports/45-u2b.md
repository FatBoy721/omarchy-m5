# 45: u2 rev 2 NATIVE (`reports/native-u2b.txt`): the wrong kernel ran, so rev 2 is untested

**Verdict:** rev 2 never ran. The log shows:
- **The wrong kernel booted.** `Linux version 7.3.0-m5n1+ … #4 … 06:39:15`, cmdline marker `m5.testmarker=N1-BIS-A2`, `m5_pmgr_allow=ans` only. That is m5-n1's kexec set, not ours. Ours is `build/usb-v1/m5next-u2/`: Image `6ca13193…`, 7.2.2-m5slim+, marker `USB-U2`, allow-list ans plus the 4 atc0 domains.
- **No m5_usb op ran.** All five `insmod m5_usb` calls failed with `version magic '7.2.2-m5slim+ …' should be '7.3.0-m5n1+ …'`. There are no dt, phandle, ps or WRITE lines, and no `m5 pmgr:` writes to atc0 (the allow-list didn't name them anyway).
- **The rest follows from that.** The gadget part ran on its own:
  - `/sys/class/udc` is empty, because no dwc3 exists.
  - `UDC bind rc=0` echoed an empty name.
  - usb0 and usb1 don't exist, and `ln` of the ecm function failed.
  - sshd did start.
  - The host sees the port's own `05ac:f014` DFU personality, as expected with ATC0 off (u0/u2: common and phymxwrap off, usb clock-gated).
- **Unrelated noise in that boot.** m5-n1's 7.3 kernel had pwrstate -110 deferred-probe timeouts on 280600000 power-controller@280/288/290/298/2e8/2f0. They come from that kernel's DT, not ours.

So the questions (did ATC0 reach actual f, did op=dev write, did dwc3 bind) are **still unanswered**. Nothing in this run tested the live-DT route.

## Fix
- **Guard:** u0 and u2 m5-exp now check `uname -r` = `7.2.2-m5slim+` and the matching `m5.testmarker=USB-U0` or `USB-U2` before doing anything. If either is wrong, they log `WRONG KERNEL/SET …` with the actual uname and cmdline and stop.
